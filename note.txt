3. PROBLEMS FACED TODAY & HOW THEY WERE SOLVED (STEP-BY-STEP EXPLANATION)
================================================================================

--------------------------------------------------------------------------------
PROBLEM 1: JSP Engine Missing in Standalone Docker JAR (Compilation Failure)
--------------------------------------------------------------------------------
- SYMPTOM:
  When running the app inside Docker on Render, JSP pages would fail to compile
  or throw 404 / internal errors.
- ROOT CAUSE:
  In "pom.xml", the dependency "tomcat-embed-jasper" had <scope>provided</scope>.
  In Maven, "provided" dependencies are excluded when building standalone 
  executable JAR files (java -jar app.jar).
- SOLUTION:
  Removed <scope>provided</scope> from "tomcat-embed-jasper" in pom.xml so that
  the Jasper JSP compiler is bundled directly inside the production JAR.

--------------------------------------------------------------------------------
PROBLEM 2: Tomcat Embedded Could Not Find JSP Views in Docker Container
--------------------------------------------------------------------------------
- SYMPTOM:
  Spring MVC forwarded view requests to "/views/index.jsp", but Tomcat returned
  404 Not Found, falling back to error dispatches and redirecting to /login.
- ROOT CAUSE:
  In Spring Boot standalone executable JARs, embedded Tomcat initializes its 
  Document Base (docBase) in a temporary directory in "/tmp/". It does not 
  automatically scan the file system for "src/main/webapp/views/".
- SOLUTION:
  1. Updated Dockerfile to copy "src/main/webapp" into "/app/src/main/webapp".
  2. Created "TomcatConfig.java" using WebServerFactoryCustomizer to explicitly
     set Tomcat's document root:
     factory.setDocumentRoot(new File("src/main/webapp"));
  3. Added resource mapping in pom.xml to bundle webapp into META-INF/resources.

--------------------------------------------------------------------------------
PROBLEM 3: Infinite Redirect Loop on <jsp:include> (ERR_TOO_MANY_REDIRECTS)
--------------------------------------------------------------------------------
- SYMPTOM:
  Visiting https://lms-app-by-abhi.onrender.com/ or /login caused Chrome to show
  "net::ERR_TOO_MANY_REDIRECTS".
- ROOT CAUSE:
  All JSP pages start with <jsp:include page="header.jsp" />.
  In Spring Boot 3 / Spring Security 6, internal servlet dispatches of type 
  "DispatcherType.INCLUDE" and "DispatcherType.FORWARD" are secured by default.
  When an unauthenticated user visited public /login, the header include was 
  intercepted as unauthenticated, redirecting back to /login in an infinite loop.
- SOLUTION:
  In "SecurityConfig.java", explicitly permitted all internal dispatcher types:
  .dispatcherTypeMatchers(
      DispatcherType.FORWARD,
      DispatcherType.INCLUDE,
      DispatcherType.ERROR,
      DispatcherType.ASYNC
  ).permitAll()

--------------------------------------------------------------------------------
PROBLEM 4: Cloud Reverse Proxy SSL Ping-Pong Loop (HTTP vs HTTPS)
--------------------------------------------------------------------------------
- SYMPTOM:
  Redirects bounced infinitely between Cloudflare HTTPS (port 443) and Tomcat 
  HTTP (port 10000).
- ROOT CAUSE:
  Render terminates SSL at its cloud router and forwards requests to the 
  container via HTTP. Tomcat did not read "X-Forwarded-Proto: https", so it 
  generated redirects with "http://...:10000". Render then redirected "http://" 
  back to "https://".
- SOLUTION:
  In "application.properties", added:
  - server.forward-headers-strategy=native
  - server.tomcat.use-relative-redirects=true
  - server.tomcat.remoteip.protocol-header=x-forwarded-proto
  This forced Tomcat to trust proxy HTTPS headers and issue clean relative 
  redirects (e.g., Location: /login) rather than absolute internal HTTP URLs.

--------------------------------------------------------------------------------
PROBLEM 5: Session IDs Appended to URLs (;jsessionid=...)
--------------------------------------------------------------------------------
- SYMPTOM:
  Redirect headers looked like "/login;jsessionid=94A58F...".
- ROOT CAUSE:
  Tomcat's default session tracking mode allows URL rewriting before cookies 
  are confirmed.
- SOLUTION:
  Added "server.servlet.session.tracking-modes=cookie" in application.properties
  to force cookie-only session management.

--------------------------------------------------------------------------------
PROBLEM 6: GitHub Push Protection Blocked Raw Aiven Database Password
--------------------------------------------------------------------------------
- SYMPTOM:
  Git rejected the commit with "remote: - GITHUB PUSH PROTECTION: Push cannot 
  contain secrets (Aiven Service Password)".
- ROOT CAUSE:
  GitHub's automated secret scanner prevents hardcoded production cloud passwords
  from being pushed to public GitHub repositories to prevent security breaches.
- SOLUTION:
  Configured "application.properties" with dynamic environment variable bindings:
  spring.datasource.url=${SPRING_DATASOURCE_URL:...}
  spring.datasource.username=${SPRING_DATASOURCE_USERNAME:...}
  spring.datasource.password=${SPRING_DATASOURCE_PASSWORD:...}
  These values are securely injected into Render via the Environment Variables tab.

--------------------------------------------------------------------------------
PROBLEM 7: Experimental Spring Boot 4.0.1 Incompatibility
--------------------------------------------------------------------------------
- SYMPTOM:
  Compilation errors occurred with Tomcat embedded classes when using parent 4.0.1.
- ROOT CAUSE:
  Spring Boot 4.0.1 is an unreleased experimental milestone.
- SOLUTION:
  Standardized "pom.xml" on the stable production LTS version: Spring Boot 3.3.4.

"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe"

   mysql -h javaready-mysql-javaready2026.j.aivencloud.com -P 26871 -u avnadmin -p LMS

      mysql -h javaready-mysql-javaready2026.j.aivencloud.com -P 26871 -u avnadmin -p LMS -e "SELECT id, name, email, role, status FROM user_master;"

   3. View Courses:
      mysql -h javaready-mysql-javaready2026.j.aivencloud.com -P 26871 -u avnadmin -p LMS -e "SELECT id, title, instructor_id FROM courses;"
